# Шаблоны брифов для фоновых агентов

Каждый бриф - самодостаточный: агент знает только то, что в нём. Подставить `<ПРОДУКТ>`,
`<D>` (абсолютный путь рабочей папки), `<ГРУППА>`, список конкурентов. Общий блок
«Ограничения» вставлять в каждый бриф.

## Общий блок «Ограничения и инструменты»

```
## Жёсткие ограничения
- Только чтение. НИКАКИХ регистраций с персональными данными, заявок, форм, сообщений в
  чаты и ботам конкурентов. Капчи не обходить. Закрыто логином - пометить и идти дальше.
- Можно: публичные лендинги, справка и база знаний, документация API, оферты, страницы
  тарифов, калькуляторы тарифов (без отправки форм), демо без регистрации, видео-обзоры,
  статьи, отзывы.
- Без кода нашего продукта, без Jira, без git.

## Инструменты
- WebSearch / WebFetch (загрузить через ToolSearch "select:WebSearch,WebFetch"). Искать
  по-русски и по-английски.
- Playwright для JS-сайтов и скриншотов (скрипт готов, не переписывать):
  <PY> -I <SKILL>/scripts/shot.py "<url>" <имя> [--imgs] [--min 300] [--selector "article"]
  с переменной окружения DISCOVERY_DIR=<D>. Пишет <D>/shots/ru-<имя>.png (full page),
  <D>/text/ru-<имя>.txt (текст страницы), картинки статьи с --imgs.
  Профиль Chrome один, запуски встают в очередь через lock - это нормально. Таймаут Bash
  300000. Имена латиницей через дефис: ru-<конкурент>-pricing.
- Скриншот страницы тарифов - обязателен для каждого живого конкурента.
- Самые информативные скриншоты открыть через Read и описать, что на них.
```

## Бриф 1. Карточки конкурентов (группа)

```
# Конкурентный разбор: <ПРОДУКТ>, группа <ГРУППА>
Дата снятия: <дата>. Мы (<компания>) делаем discovery <ПРОДУКТ>. У нас уже есть: <3-5 строк
о нашем продукте и цене> - нужно сравнение с нами.
Нужно «каждую цифру и каждую функцию» у каждого конкурента из списка: <список с URL>.

<Общий блок>

## Карточка конкурента
1. Сайт, юрлицо (название, ИНН/ОГРН из оферты или футера), год запуска, площадки. Жив ли
   сервис - если мёртв, пометить с доказательством.
2. Тарифы целиком: цена за месяц и год, за что тарифицируют (кабинеты, артикулы, оборот,
   %), лимиты, триал (длина, нужна ли карта), скидки за 3/6/12 мес, промокоды, партнёрка,
   бесплатный тариф. Цифры как на сайте, с URL. Посчитать цену месяца для профилей:
   <профили из наших данных>.
3. Функции полностью: весь список пунктов меню и тарифа конкурента дословно (даже если у нас
   такого нет), плюс по чек-листу функций продукта: <список функций, которые важны -
   из 00-our-product.md и матрицы>. Для каждой - есть / частично / нет, со ссылкой на
   справку.
4. Заявленные результаты и соцдоказательства: число клиентов, кейсы, цитаты с URL.
5. Отзывы: Отзовик, irecommend, vc.ru, Pikabu, TenChat, Habr, YouTube, публичные чаты,
   подборки «лучшие сервисы 2025/2026». Что хвалят, на что жалуются - короткие цитаты.
6. Слабые места и дыры, которые можно закрыть.
7. Финансы юрлица: выручка и прибыль по годам (checko.ru, rusprofile.ru, list-org.com,
   audit-it), сотрудники, дата регистрации, ОКВЭД, группа компаний.
8. Трафик сайта (pr-cy.ru/a/<домен>, be1.ru/stat/<домен>, similarweb) - визиты в месяц с датой.

## Формат выхода
Файл <D>/notes/comp-<группа>.md. Раздел `## <Название>` с подзаголовками 1-8. Каждая цифра
с URL. В конце - строка по каждому в таблице:
| Название | Площадки | Цена входа ₽/мес | Модель оплаты | <ключевые функции колонками> | Триал | ₽/мес профиль A | ₽/мес профиль B | Юрлицо | Выручка последний год |
и список НОВЫХ игроков, найденных по ходу (имя + URL).
Пиши по-русски, обычный дефис вместо длинного тире, цифры цифрами, без воды.
Итоговое сообщение: 10-15 строк главного + путь к файлу.
```

## Бриф 2. UX конкурентов

```
# UX конкурентов: <ПРОДУКТ>
Цель: как у конкурентов устроен интерфейс, чтобы сравнить с нашим и спроектировать лучше.
Рынок и тарифы уже сняты в <D>/notes/comp-*.md - не повторять, цену брать оттуда.

<Общий блок>

## По каждому продукту (у каждого факта URL)
1. Экраны: главный дашборд; ключевые отчёты; настройки (ввод себестоимости, налогов и т.п.);
   онбординг и первый запуск (пустые состояния, чек-лист); массовые действия (импорт Excel).
2. Как объясняют «почему цифра такая»: расшифровка, тултипы, детализация расчёта.
3. Уведомления: Telegram, почта, в интерфейсе; какие события.
4. Мобильная версия, Telegram-бот, приложение.
5. Сильное в UX (1-3) и слабое (1-3).

## Источники UX
- Справка и база знаний со скриншотами - главное (shot.py --imgs). Многие вики отдают
  llms.txt или .md-версии.
- YouTube: <PY> -I <SKILL>/scripts/yt.py search "https://www.youtube.com/results?search_query=<запрос>"
  и yt.py video <url> - описание и главы. Ссылка на видео - у факта.
- 3-8 страниц справки на продукт, самые насыщенные.

## Формат
<D>/notes/ux-<группа>.md, раздел на продукт. В конце «Что не удалось».
Итог: 5-8 строк главного + путь.
```

## Бриф 3. Голос клиента в Telegram (один агент на всю сессию)

```
# Telegram: что клиенты говорят про <ТЕМА>
Сессия Telethon одна - ты единственный, кто её открывает. Только чтение: ничего не
отправлять, не вступать в чаты, не ставить реакции.

Скрипты: <SKILL>/scripts/tg_dialogs.py (список диалогов и id), tg_search.py (поиск
каналов по словам), tg_fetch.py <config.json> (выгрузка), tg_comments.py (комментарии
к постам канала). Окружение: DISCOVERY_DIR=<D>, TG_ENV=<путь к .env>, TG_SESSION=<путь к
копии сессии>. Выгрузка пишется в <D>/tg-raw/<имя>.jsonl.

Охват - ВСЕ чаты по теме, не выборка: свои каналы и чаты, все чаты поддержки (включая
старые и мигрированные копии групп), фокус-группы, чаты продаж, чаты клиентов, а также
глобальный поиск по ключевым словам по всем диалогам аккаунта, включая личные переписки с
клиентами (`functions.messages.SearchGlobalRequest`). Обращения в бот поддержки (если он
пишет в БД) - снимать SQL-ом отдельно, это часть голоса клиента.

Шаги:
1. tg_dialogs.py - найти чаты клиентов, свои каналы и чаты, все чаты поддержки, фокус-группы.
2. tg_search.py <слова> - найти каналы конкурентов и тематические чаты.
3. Конфиг выгрузки: чаты {id: имя}, full - что выгрузить целиком, keywords - слова темы
   и имена конкурентов, cut - дата отсечки (обычно 12 месяцев).
4. tg_comments.py по каналам конкурентов с комментариями.
5. Разбор: частые боли (с подсчётом), запросы функций, упоминания конкурентов (кто, за что
   хвалят и ругают, «перешёл с X на Y»), цены, которые называют. Цитаты короткие, с чатом
   и датой (ссылка t.me/<username>/<id>, если чат публичный).

Формат: <D>/notes/telegram.md - таблица чатов (сколько сообщений снято), топ-болей с
числами, упоминания конкурентов с цитатами, запросы функций, что говорят про нас.
Итог: 10 строк главного + путь.
```

## Бриф 4. Механика площадки и регуляторика

```
# Механика и правила: <ПРОДУКТ>
Как площадка устроена в части, которую закрывает продукт: отчёты, API (методы, лимиты,
что изменилось в 2025-2026), налоги и законы (УСН, НДС, маркировка), сезонность,
планы площадки (свой встроенный инструмент = главный риск). Ссылки на официальную
документацию и новости. Формат <D>/notes/mechanics.md, итог 10 строк + путь.
```

## Бриф 5. Рынок (TAM/SAM/SOM)

```
Сколько бизнесов на рынке (продавцов WB/Ozon с продажами, по размеру), сколько платят за
аналитику и финучёт, средний чек сервисов, выручка лидеров (из финансов юрлиц) как
нижняя граница рынка. Сверху вниз и снизу вверх, у каждого числа источник.
Формат <D>/notes/market.md.
```

## Бриф 6. Поиск пропусков от рынка

```
Задача: найти ВСЕ функции конкурентов, которых нет у нас и/или нет в отчёте. Список строим
от рынка, а не от наших функций.
Входы: <D>/text/ru-*.txt (без -imgs), <D>/notes/comp-*.md и ux*.md, голос клиента
(<D>/notes/telegram.md, выгрузка поддержки), наш инвентарь <D>/notes/00-our-product.md и код
(только чтение), текущий отчёт <D>/artifact/*.html.
1. Выписать пункты меню, разделы и функции каждого конкурента, нормализовать синонимы
   (ABC = АВС, ДДС = cash flow, подсорт = расчёт поставки).
2. Частотный счёт: у скольких разных сервисов, кто, 1-2 доказательства.
3. Для частоты 3+ и всего, что просят клиенты: есть ли у нас (путь к файлу или «не
   найдено»), есть ли в отчёте (grep).
4. Запросы клиентов, которых нет ни у нас, ни в отчёте.
Выход <D>/notes/gaps.md: таблица по частоте; «пропущено и нет у нас» с «зачем селлеру» и
важностью; «есть у нас, но не подано как преимущество»; «отсеяно». Итог: 10-15 строк + путь.
```
